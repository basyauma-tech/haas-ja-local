# 実モデルの数値検証（Mac、2026-11-08）

自前の純PyTorch実装（`haas_ja_local.torch_model`）を、同じチェックポイントから第三者が書き出したfp32 ONNXと突き合わせた。FLEURSの6発話すべてで、前処理・エンコーダ・結合ネットワークの誤差が閾値を下回り、トークン列も一致した。

途中でサブサンプリングのマスク漏れを1件見つけて直した（後述）。修正前は6本中4本でエンコーダの相対誤差が最大8.17e-02あった。

## 測ったもの

`scripts/verify_numerics.py`で各発話について次を測った。

- (a)自前の`log_mel`と参照の`haas_ort.logmel`の差。有効フレームでのmax abs。参照は窓とメルフィルタバンクをlibrosaで作り直してbf16に丸めている。自前はチェックポイントのbf16バッファを使う。両者の差は窓・フィルタバンクとも0だった。
- (b)同じ自前melを入れたときのエンコーダ出力の相対誤差`max|a−b| / max|b|`。フレームごとの値も出し、最終フレームとそれ以外を分けた。
- (c)参照greedyがたどった各ステップの結合ネットワークlogitsの相対誤差。参照エンコーダの出力フレーム、トークン、参照側の入力状態を両方の予測・結合ネットワークに入れ、ステップごとに独立に比べた。出力状態の相対誤差も併記する。
- (d)自前のgreedy（自前mel→自前torch）と、参照のgreedy（参照logmel→参照ONNX→参照の`greedy_tdt`）のトークン列が一致するか。参照ONNXに自前melを入れた場合の一致も記録した（こちらも6本とも一致）。
- (e)書き起こし文と正解文。

閾値は(a)が1e-3未満、(b)と(c)が1e-4未満、(d)は全発話で一致。

再現手順は次のとおり。結果は`var/verify/numerics.json`に出る。

```sh
uv run --extra convert --extra onnx --with librosa python scripts/verify_numerics.py \
  --nemo var/upstream/Haas-ja-v1.0.nemo --reference-dir var/reference/sanami-onnx \
  --clips var/bench/clips --out var/verify/numerics.json
```

## 見つけた不一致と対処: サブサンプリング内のマスク

初回の実行では、(b)のエンコーダ相対誤差が4本で閾値を大きく超えた。

| id | melフレームを8で割った余り | (b)エンコーダ相対誤差（修正前） | 最終フレーム（修正前） | 1e-4を超えたフレーム |
|---|---|---|---|---|
| 1828 | 4 | 6.15e-02 | 1.19e-02 | 全131フレーム |
| 1983 | 4 | 5.98e-03 | 5.98e-03 | 全326フレーム |
| 1927 | 4 | 2.65e-02 | 7.08e-03 | 全164フレーム |
| 1854 | 2 | 8.17e-02 | 1.42e-02 | 全117フレーム |
| 1829 | 0 | 7.10e-07 | 3.88e-07 | なし |
| 1835 | 0 | 1.55e-06 | 3.61e-07 | なし |

(a)と(c)は修正前から閾値内で、(d)も6本とも一致していた。外れたのは、melの有効フレーム数が8の倍数でない発話だけだった。

原因は次のとおり。NeMo v2.7.0の`ConvSubsampling`は畳み込み列を`MaskedConvSequential`で包む。各層の直前で時間軸の有効長より後ろを0にし、stride 2の畳み込みのたびに有効長を`(L + 2·pad − kernel) // stride + 1`へ更新する。自前の実装はこのマスクを持たず、0埋めのmelをそのまま畳み込んでいた。

1段目の出力の0埋め部分には、バイアスとReLUで0でない値が入る。有効長が8の倍数でないと、2段目以降で最後の有効フレームがその値を読む。最初に汚れるのは最終フレームだけだが、自己注意が全フレームを参照するので、誤差はエンコーダ出力の全フレームへ広がる。「最終フレームだけ外れる」形にはならなかった。

確認として、melを有効長で切り詰めてから入れると（マスクと等価）、修正前のコードでも6本とも相対誤差1e-5未満になった。参照ONNXはNeMoから書き出したものなので、このマスクを含んでいる。つまりNeMoはサブサンプリングの内部でマスクする、と判断した。

対処として、`ConvSubsampling.forward`に有効長を渡し、NeMoと同じ規則で各層の前にマスクを掛けるようにした。テストは先に書いて失敗を確かめた。

- `test_encoder_ignores_padding_frames`: 有効長の直後からmelを変えても出力が変わらない。従来版は受容野の分だけ後ろから変えていたため、この不一致を見逃していた。
- `test_encoder_padded_input_matches_unpadded`: 0埋めしたmelと、有効長で切り詰めたmelの出力が一致する。

MLX実装とONNX書き出しも、同じマスクを入れる必要がある。

## 回帰テスト

`tests/data/expected_tokens.json`に、id 1854と1828の自前トークン列を保存した。どちらも有効フレーム数が8の倍数でなく、上記のマスクを通る。`tests/test_real_model.py`の`test_real_torch_reproduces_expected_tokens`が、自前torch実装の出力がこれと一致することを確かめる。音声はリポジトリに含めず、環境変数`HAAS_JA_CLIPS_DIR`のディレクトリから読む（未設定ならskip）。

```sh
HAAS_JA_NEMO=var/upstream/Haas-ja-v1.0.nemo HAAS_JA_CLIPS_DIR=var/bench/clips \
  uv run --extra convert pytest -m real_model -v tests/test_real_model.py
```

修正前のコードでもこの2本のトークン列は参照と一致していた。マスク漏れそのものはユニットテストで検出する。
